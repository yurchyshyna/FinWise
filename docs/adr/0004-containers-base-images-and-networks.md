# ADR-0004: Базові образи та ізоляція мереж у контейнерах

- Status: Accepted
- Date: 2026-11-15

## Context

Систему потрібно запускати в контейнерах однією командою. Образи мають бути невеликими, процеси не повинні працювати від root, а база даних має бути доступна лише бекенду та воркеру.

## Considered Options

Базові образи для Python:
1. python:3.12 (повний);
2. python:3.12-slim;
3. python:3.12-alpine.

Мережі:
1. одна спільна мережа для всіх контейнерів;
2. дві мережі: frontend-net (веб і API) та backend-net (API, воркер і база).

## Decision

- Для API та воркера обрано python:3.12-slim. Alpine менший, але використовує іншу системну бібліотеку (musl), і з деякими Python-пакетами бувають проблеми зі збіркою. Slim достатньо малий і безпроблемний.
- Для фронтенду використано багатоетапну збірку: node:20-alpine збирає застосунок, а у фінальний образ потрапляє лише готова статика в nginx-unprivileged, який працює не від root.
- Обрано дві мережі. База даних підключена лише до backend-net, а ця мережа позначена як internal, тому ззовні та з фронтенд-контейнера до бази достукатися не можна.
- Усі налаштування (паролі, хости, порти) передаються через змінні оточення з файлу .env, який не потрапляє в Git.

## Consequences

- Образи невеликі, процеси працюють від непривілейованого користувача, а база захищена на рівні мережі.
- Мінус: у внутрішній мережі backend-net контейнери не мають виходу в інтернет. Коли воркеру знадобиться звертатися до банку чи сервісу сповіщень, для нього потрібно буде додати окрему мережу з виходом назовні.
